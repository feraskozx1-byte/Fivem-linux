# نتيجة تنفيذية جديدة: مصدر1477 هو تدرج الحلقة

**التتبع سجل1478دخولًا إلى lookup، بالفهرس0ثم1ثم2…حتى1477، على نفس buffer وجدول NTDLL. العدد المعلن للأسماء بقي1468 في كل دخول. أول تجاوز هو1468؛ الانهيار عند1477 أثر لاحق.**

هذا يستبعد فرضية أن المسار المرصود بدأ بفهرس ثابت1477. ولا يحدد اسم export مطلوبًا؛ مطابقة1477 باسم في مرجع Windows السابق لا تفسر اختيار الفهرس.

## التعديل والبناء والاختبارات المنفذة

- بُنيت أداة debugger منفصلة، وبرنامج عينة صغير، باستخدام clang/llvm/lld المثبتة. لم يُعدّل Wine أو FiveM أو Adhesive.
- العينة استدعت IndexBoundary بالقيم `[0,1,9,1467,1477]`. سجلت الأداة القيم الخمس بالترتيب، وانتهت العينة بكود0 بعد تحقق checksum. النتيجة في `fixture-validation.json`.
- بعدها شُغّل FiveM الحقيقي في تخطيط Phase2 المعزول، بالشبكة معطلة. وضعت الأداة hardware execute breakpoint عند Adhesive+`D9FDD5`، دون كتابة تعليمات إلى المكتبة. المصحح وDR0 ظاهران. SetThreadContext يضبط debug registers وResume Flag اللازم لاستئناف تعليمة breakpoint الأصلية؛ لا تغيير للفهرس أو RIP أو نتائج API. استثناء AV الحقيقي يُعاد NOT_HANDLED.
- سجل `private/index-sequence/adh-index-trace.txt` التسلسل الكامل دون الوصول إلى حد4096 أو خطأ debugger. `sequence-evidence.json` و`sequence-excerpt.txt` يلخصانه ويتيح `analyze-trace.py` إعادة التحقق.

| القياس | النتيجة |
| --- | --- |
| الفهارس المرصودة | كل عدد من0إلى1477، دون قفز |
| مجال الأسماء الصالح | 0..1467 |
| أول قراءة جدول غير صالحة دلاليًا | index1468، بداية جدول ordinals |
| قراءات الجدول بعد النهاية حتى AV | 10 |
| AV | نفس RVA `D9FEC5` وRAX=`0x130012` |
| تحميل Adhesive | بقي الفشل998 ثم fallback الموجود |

عند1468تُقرأ قيمتا ordinal0و1 كـDWORD=`0x10000`. تستمر الحلقة في قراءة أزواج أخرى حتى18و19عند1477، فينتج`0x130012`. بعض القراءات غير الصحيحة تقع في ذاكرة قابلة للقراءة؛ لذلك **أول AV لا يحدد أول انتهاك للحدود**. إثباتنا يأتي من الفهارس ومحتوى الجدول الفعلي، لا من رمز998 وحده.

## السبب والعائق الحالي

ثبت موضع إخفاق عقد جدول PE: الحلقة داخل initializer تستمر بعد NumberOfNames. لم يُثبت لماذا شرط استمرارها يسمح بذلك: بحث عن اسم مفقود، حد مختلف، أو مدخل داخلي آخر. لا ندعي أن الحلقة لا تنتهي إطلاقًا، أو أن1477 حدها المقصود؛ توقف القياس عند الانهيار.

راجعنا مسار حل الأسماء في مصدر [Wine11.0 loader.c](https://github.com/wine-mirror/wine/blob/wine-11.0/dlls/ntdll/loader.c): البحث العام يستخدم NumberOfNames ويتحقق من hint قبل استخدامه. هذا مرجع upstream، لا إثبات تطابق كل patches الخاصة بـCachyOS. التتبع الحالي يرصد تعليمات داخل Adhesive؛ لم يكشف مخالفة API عامة قابلة للترقيع. كذلك لم نجد إصلاحًا للحلقة في [PR4095](https://github.com/citizenfx/fivem/pull/4095)، الذي يعالج UI/SEH.

**لا يوجد إصلاح تشغيل مثبت بعد.** تعديل index أو وقف الحلقة خارجيًا أو توسيع الذاكرة لن يثبت اكتمال الحماية، فلا نطبقه. العائق المحدد هو عقد إنهاء iterator المغلق: نحتاج من Cfx.re هوية البحث المقصود وقيم شرط الاستمرار عند1467/1468، ومصدر الحد المستخدم. بعد تسمية API عامة ناقصة يمكن إنشاء تنفيذ Wine صحيح واختباره. مسودة الطلب في `CFX_REPORT.md`، لم تُرسل.

## الحفظ والتراجع وإعادة التحقق

كل الكود الجديد داخل هذا المجلد، ونسخ ما قبل تعديل observer محفوظة، والفرق في `observer-changes.patch`. سجلت محاولتا إعداد أداة غير ناجحتين منفصلتين: مشكلة stack-probe عند الربط، ثم مسار executable غير موجود قبل تشغيل العينة. صححنا الأداة؛ ليستا نتائج لـAdhesive. أزال Proton ربط S في prefix التشخيصي أثناء المحاولة الفاشلة؛ أُعيد إلى `/home/feras`، ويحفظ runner الربط ويستعيده بعد كل تشغيل. يستخدم debugger مسارات Z الثابتة. الـprefix الرئيسي لم يُستخدم.

```bash
# إعادة حساب الأدلة الحالية، دون تشغيل FiveM:
python3 Diagnostics/2026-11-05-Adhesive-Index-Trace/analyze-trace.py

# بناء/تحقق مستقل، مع tags جديدة عند إعادة التشغيل:
bash Diagnostics/2026-11-05-Adhesive-Index-Trace/build-trace.sh
python3 Diagnostics/2026-11-05-Adhesive-Index-Trace/run-trace.py --fixture --tag fixture-new
python3 Diagnostics/2026-11-05-Adhesive-Index-Trace/validate-fixture.py --tag fixture-new

# يتطلب نجاح العينة المطابقة للبناء؛ لا حاجة لتكراره دون قياس جديد:
python3 Diagnostics/2026-11-05-Adhesive-Index-Trace/run-trace.py --tag iterator-new
```

لا يوجد DLL تشغيل جديد لاعتماده أو patch نظام يحتاج تراجعًا. اختبارات السيرفرات لم تبدأ، لأن تهيئة الحماية ما زالت تفشل.

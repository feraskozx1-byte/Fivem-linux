Prepared locally; not sent. No protection binary or policy was changed, no Wine masking, no tickets or server tests.

1. Built a CoreRT-only experiment from pinned PR4050 source plus the existing compatibility changes. Under Wine it does not install HardErrorScope's RtlRaiseException/ZwQueryDebugFilterState diagnostic hooks. Native Windows path and security component selection are unchanged. Adhesive still raises read AV at RVA D9FEC5 in PROCESS_ATTACH, returns0 and client logs998. Original CoreRT/PDB links were restored. This experiment is not an operational fix.
3. Wine +file logging now identifies both actual pre-fault reads: ntdll.dll, request0x13D000/actual0x13C904; win32u.dll, request0x61000/actual0x600B8. Both report success. These are not speculative file identities inferred from sizes.
4. A newly built independent probe replays those files and observed NtOpenFile options/access/share, FileStandardInformation and NtReadFile calls under the same prefix/runtime. Fifteen checks pass: actual count equals EOF and matches the host trace; data fingerprints match the actual files; unread tails retain canary bytes. AllocationSize equals the larger requested amount. No count/data mismatch was observed. Fingerprint comparison uses FNV1a64; SHA256 of source files is recorded separately. This is not a native Windows differential test.
5. Public PE structural checks on these inputs pass for section/export/ordinal bounds and name ordering; this does not certify private initializer compatibility with Wine's system-module layout.

The older request for the identities and read counts of the two inputs is now partially resolved. The remaining precise request is the buffer/index contract for this initializer: which input/table is supposed to produce the read index, what valid bounds should apply, and which host/component ABI set is supported for the exact Adhesive hash? A sanctioned diagnostic build logging only lengths and input identity, or symbolication sufficient to identify the public input contract, would allow a justified next compatibility test. No protection logic change or permissive API shim is proposed.

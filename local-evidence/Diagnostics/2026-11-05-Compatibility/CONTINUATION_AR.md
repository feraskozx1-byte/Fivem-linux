# متابعة التنفيذ — دون إعادة الاختبارات القديمة

- بقي إصلاحا CoreRT وSEH مطابقين للـpatches السابقة بايتياً؛ نتائج اختبارات المصدر وتجارب Proton السابقة ما زالت صالحة. لم يُبنَ DLL جديد ولم يُختبر العميل الكامل.
- **إصلاح جديد:** `XBRInit.cpp:87` يقبل DefaultBuild فقط إذا كان ضمن الإصدارات المدعومة؛ تجاهل 3889 غير المدعوم يحافظ على مسار الاختيار الافتراضي/القديم. لم تتغير ملفات INI. الاختبار يستخرج دالة الإنتاج ويفتح قائمة الدعم الحقيقية ويستخدم defaults الفعلية: 36 حالة عبر FiveM/RedM/LibertyM تحت ASan/UBSan، مع إثبات فشل المصدر السابق. لا يضيف الإصلاح دعم 3889.
- **توافق مع شرط إظهار البيئة:** أزيل الاستدعاء الوحيد لـWineCompat_InstallHooks من EarlyMode_Init، مع الإعلان والتعليق المرتبطين به. بقي ملف الدالة القديم محفوظاً لكنه بلا مستدعٍ. اختبرنا دالة البداية الفعلية بمكونات وهمية: لا تفعيل لخطاف الإخفاء، وترتيب الإنشاء وPreInitGame محفوظ. المصدر السابق يفشل الاختبار. هذا لا يضمن قبول الحماية، وقد يغيّر رفض المكونات الرسمية للبيئة مستقبلاً؛ لم تُغيّر الثنائيات الحالية.
- **تحقق ترجمة جديد:** أنتج clang-cl ملف COFF لـWindows AMD64 من دوال SEH الحالية دون تعديلها، مع LaunchMode.h الفعلي وواجهة MinHook عند commit المشروع `b03840395033006c888288ac00a4608d8e2684cf`. استُعيض عن أنواع وتصريحات Win32 فقط لغياب SDK. نجحت /W4 /WX مع السماح بامتداد تحويل المؤشرات المستخدم أصلاً في مسار MSVC. هذا فحص ترجمة جزئي؛ ليس بناء CoreRT أو ربطه أو اختبار MinHook فعلياً.
- لا MSBuild/SDK أو solution مولدة أو ملفات object/Shared.lib قابلة لإعادة الربط محلياً؛ MinHook وudis86 وبقية اعتماديات البناء المباشرة غير مهيأة. لا توجد مخرجات مفيدة لذلك في workspace FiveM المرتبط أيضاً. لم يُنزّل مستودع أو تُثبت حزمة أو يبدأ Actions/build.

**مسار البناء الجاهز:** `build-citicore.py` يخطط افتراضياً، ويشغّل هدف CitiCore فقط عند تمرير `--execute` على Windows مجهز بـVS 2022. يستخدم incremental build، ولا ينظف أو ينزّل اعتماديات أو يستبدل DLLs في مجلدي التشغيل. restore اختياري صريح. نجح فحص امتناعه عن البناء عند غياب المتطلبات. الخطة الحالية في `build-validation/citicore-build-plan.json`.

```powershell
python Diagnostics/2026-11-05-Compatibility/build-citicore.py --execute
```

يُنفذ من نسخة المشروع المنقولة إلى بيئة Windows مجهزة، بعد إعداد المصدر والاعتماديات وتوليد solution. Target CitiCore ينتج CoreRT.dll مع Shared واعتمادياته؛ تعديل EarlyMode جزء منه. تعديل XBRInit ضمن Shared/SharedLibc، لذلك يحتاج إعادة ربط المستهلكين المعنيين لتعميمه، وليس تحديث CoreRT وحده ضماناً لتحديث جميع العمليات.

**العوائق المحفوظة:** لم تحدد الأدلة API مفتوحة المصدر مسؤولة عن Adhesive+0xD9FEC5؛ لا مبرر لتكرار التجربة أو تعديل المكوّن المغلق. ربط الحساب وتذكرة cfxTicket2 مساران مختلفان؛ لا إصلاح مثبت للـROS403 أو CURL52/56. تبقى قيود الدعم الموثقة سابقاً وكود المصادقة/الحماية غير المتاح عائقاً. لم تُجر محاولات دخول أو تنقل جلسات.

وجدت في prefix العمل overrides متباينة: FiveM.exe=win11 ومفاتيح لبعض عمليات اللعبة/ROS=win7. لم تُعدل؛ الثنائيات القديمة باقية وبعض overrides استُخدمت سابقاً لتجنب أعطالها. المقارنة بإعداد موحد تكون في نسخة prefix منفصلة بعد توفر DLL المبني.

**الحفظ:** الملفات التسعة المسجلة سابقاً في مجلدي التشغيل تطابق hashes الأصلية. لم تتغير prefixes أو إعدادات Heroic أو الحسابات. بقي CRLF في ملفات CoreRT/SEH واحتُفظ بنهايات الأسطر الأصلية للملفين الجديدين والنسخ الاحتياطية. `continuation-only.patch` للتغييرين الجديدين؛ `all-current-source-fixes.patch` يجمع الملفات الأربعة. النتائج الجديدة في `continuation-validation.txt`.

**الخطوة الأعلى قيمة:** بناء CitiCore مرة واحدة في بيئة Windows مجهزة، ثم اختبار CoreRT الناتج في نسخة تشغيل معزولة؛ لا يوجد مبرر لبناء العميل كله أو متابعة محاولة فرض قبول الحماية.
